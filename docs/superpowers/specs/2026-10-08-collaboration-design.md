# Audit Evidence 협업 기능 보강 설계

상태: 구현 전 검토안 · 2026-10-08

## 목적
기존 audit-evidence-agent에서 외부 담당자 초대, 문서 제출, 수정 요청, 재제출, 독립 검토자 재승인을 하나의 사용자 흐름으로 완성한다. 기존 금융·감사 프로젝트의 목적을 유지하며 합성 데이터 데모와 실제 운영 경험을 구분한다.

## 선택한 접근
기존 React/TypeScript + FastAPI + SQLAlchemy 구조를 확장한다. 전체 Next.js 전환이나 별도 서비스 신설은 이번 단계에 포함하지 않는다. 기존 데이터베이스 권한·작업 큐·감사 이력을 재사용한다.

## 외부 참여자 초대
- 검토자가 자신이 접근할 수 있는 요청에 제출 전용 초대를 만든다. 유효 기간은 기본 24시간, 최대 7일이다.
- 암호학적 난수 토큰을 생성하고 DB에는 해시만 저장한다. 원문은 생성 응답에 한 번만 제공하며 로그·감사 이벤트에 저장하지 않는다.
- 초대는 요청 한 건에만 적용한다. 외부 참여자는 요청 조회·문서 제출만 가능하고 승인·다른 요청 조회는 불가능하다.
- 링크 열기만으로 소비하지 않는다. 명시적 수락 POST에서 한 번만 교환하고 요청에 한정된 외부 세션을 만든다. 동시 수락은 한 건만 성공한다.
- 초대 회수는 이미 발급된 해당 외부 세션도 무효화한다. 세션은 초대 만료 이후 사용할 수 없다.
- 프런트엔드는 URL fragment로 토큰을 받고 즉시 주소에서 제거한다. Referrer-Policy: no-referrer와 토큰 응답 Cache-Control: no-store를 적용한다.
- 익명 수락에는 입력 제한과 시도 제한을 둔다. 이메일 소유 확인·SSO를 구현했다고 주장하지 않는다. 이메일 발송 대신 복사 가능한 링크를 제공한다.

## 문서 버전과 재승인
- 기존 문서 내용과 승인 이벤트를 덮어쓰거나 삭제하지 않는다.
- 수정 문서는 같은 요청의 특정 문서를 대체하는 새 버전으로 제출한다. 원문 digest·작성자·시각·이전 버전 연결을 보존한다.
- 최신 활성 버전만 현재 사실 추출·충돌 판단에 사용한다. 이전 버전은 이력에서 계속 확인한다.
- 수정 요청 상태에서는 담당자가 새 버전을 제출한다. 승인 완료 상태에서는 검토자가 사유와 현재 버전을 지정해 재검토를 열어야 한다.
- 재검토 시작 시 기존 승인은 이전 버전의 승인으로 남고 현재 승인 효력은 해제된다. 처리 완료 후 다른 검토자가 다시 승인한다.
- 요청 버전 확인과 DB 잠금으로 동시 수정·오래된 승인·중복 재검토를 차단한다. 진행 중인 문서 작업이 있을 때 대체를 거절해 오래된 작업 결과가 최신 상태를 덮어쓰지 않게 한다.
- 제출자 자기승인 금지, 조직 경계, 요청별 접근 범위를 유지한다.

## 데이터와 배포
초대·외부 세션·문서 대체 관계를 별도 테이블로 추가한다. 기존 테이블의 파괴적 변경을 피하고 PostgreSQL RLS 대상에 신규 조직별 테이블을 포함한다. 기존 SQLite와 PostgreSQL 자료를 유지하는 마이그레이션 및 되돌리기 절차를 기록한다. 공개 데모에는 합성 문서만 사용한다.

## 화면
검토자: 초대 생성·회수, 수정 요청, 재검토 시작, 버전 이력·변경 비교.
외부 참여자: 초대 수락, 배정된 요청 조회, 문서 제출·수정본 제출.
검토자는 이전 승인과 현재 검토 상태를 별도로 확인한다. 원문 비밀 토큰은 이력에 노출하지 않는다.

## 검증과 완료 기준
- 만료·회수·재사용·동시 수락과 요청/조직 간 접근 차단 테스트.
- 실제 PostgreSQL 런타임 역할에서 신규 테이블 RLS 테스트.
- 수정본 처리 후 이전 문서가 현재 충돌 판단에서 제외되는지 확인.
- 오래된 버전 승인, 자기승인, 승인 후 직접 제출, 작업 진행 중 대체 차단 테스트.
- 별도 브라우저 세션으로 초대→제출→수정 요청→재제출→승인→재검토→재승인 확인.
- 기존 테스트, TypeScript 빌드, 브라우저 테스트, main 반영 및 공개 배포 확인. 화면 캡처·검증 기록·README 갱신.

## 다음 단계
PDF/이미지 OCR과 원문 위치 표시, 실제 LLM 추출·오류 평가를 후속 단계로 진행한다. 실제 로그인·지속 파일 저장은 사용할 인증·저장소와 무료 범위를 확인한 뒤 연결한다. 이번 설계의 완료를 전체 보강 완료로 표현하지 않는다.

## 경력 표현
레드브릭 프리랜서 경험은 사용자가 개발팀 리딩 경험으로 제시한 사실을 반영하되, 팀 규모·기간·채용·코드리뷰·일정관리 범위는 확인 후 이력서에 구체화한다. 이번 프로젝트의 운영 문서를 과거 팀 리딩 실적으로 바꾸지 않는다.
